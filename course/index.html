RDS Key Feature: Read-Only Instances & Offloading

Read/Write Splitting & Read-Only Query Offloading

Offload SELECT Query Pressure

In typical web applications, read requests account for over 80% of database traffic. RDS allows architects to attach multiple read-only instances to offload intensive SELECT queries from the primary instance.

Independent Specifications & Scaling

  • Flexible Sizing: Read-only instances can use different compute and memory specifications from the primary instance, scaling independently.
  • Zero Maintenance Overhead: Read-only replicas automatically synchronize account credentials and database tables directly from the primary.

Unified Read/Write Splitting Endpoint

With a single read/write splitting endpoint, RDS automatically routes write queries (INSERT/UPDATE/DELETE) to the primary instance and distributes read queries across read-only instances.

Section 4: Messaging & Integration

Message Service: Queue Model vs. Topic Model

Queue Model: Point-to-Point Task Distribution (1:1)
Topic Model: Publish/Subscribe Fan-Out Broadcast (1:N)

Queue Model (Worker Processing)

  • Point-to-Point Delivery: Each message is retrieved and processed by exactly one active worker consumer.
  • Message Invisibility Timeout: When a worker receives a message, it becomes invisible to other workers. If the worker fails, the message reappears for another worker.
  • Use Cases: Order transaction processing, background video transcoding, asynchronous batch jobs.

Topic Model (Publish/Subscribe Notification)

  • Broadcast Fan-Out: A single published message is duplicated and distributed to multiple heterogeneous endpoints.
  • Multi-Protocol Subscribers: Push notifications directly to HTTP endpoints, Email, SMS, or downstream SMQ queues.
  • Use Cases: System event alerts, real-time user notification broadcasts, multi-system status synchronization.

Alibaba Cloud – Elastic IP (EIP)

Floating Public IP

Elastic IP (EIP)

An Elastic IP (EIP) address is a public IPv4 address resource that you can purchase and manage independently.

Unlike fixed public IPs, EIPs are decoupled "floating" IPs that can be bound, unbound, and moved between ECS instances, SLB load balancers, and NAT Gateways in seconds without service restarts.

EIP vs. Fixed Public IP Comparison

Architectural Feature Elastic IP (EIP) Fixed ECS Public IP
Lifecycle Independence Yes (Retained when ECS is deleted) No (Released with ECS)
Dynamic Migration Yes (Move between ECS, SLB, NAT) No (Locked to single ECS)
Multi-Line BGP Bandwidth Supported (BGP multi-ISP routing) Standard IP routing only
Shared Bandwidth Packages Supported (Share quota across IPs) Dedicated bandwidth only

High Availability Rule: During an emergency instance failure, architects can immediately rebind the production EIP to a standby ECS instance or NAT Gateway, restoring public traffic in seconds without DNS record propagation delays.

Section 6: Security, Identity & Operations

Alibaba Cloud – Resource Access Management (RAM)

RAM Identities, User Groups, Roles & Resource Authorization
Identity & Governance

RAM Core Functionality

Resource Access Management (RAM) enables organizations to centrally control which people, groups, and automated services can perform specific actions on specific cloud resources.

Architectural Best Practices (from Courseware)

  • Manage Permissions via Groups: Assign policies to User Groups rather than individual users for clean administrative lifecycle management.
  • Enforce Least Privilege: Grant only the minimum permissions necessary for users to complete assigned business duties.
  • Enable MFA & Password Policies: Require Multi-Factor Authentication (MFA) and strict rotation for privileged administrative accounts.
  • Use RAM Roles & STS: Assign RAM Roles to ECS instances and applications to obtain temporary, auto-rotating STS credentials instead of embedding permanent AccessKeys.

Practice Scenario 1: Decoupled Multi-Tier Web Architecture

Question 1 An enterprise e-commerce platform is migrating its core retail application to Alibaba Cloud. The system experiences extreme traffic surges during flash sales. The architect requires: (1) an elastic compute tier that automatically scales instances based on CPU utilization, (2) a managed relational database that offloads intensive reporting and read queries without degrading write throughput, and (3) an asynchronous message queue to buffer transaction messages so that downstream fulfillment services can process orders at a controlled pace. Which combination of Alibaba Cloud services meets all architectural requirements?
  • A Elastic Container Instance (ECI) + Tablestore + Managed Apache Kafka
  • B Elastic Compute Service (ECS) with Auto Scaling + ApsaraDB RDS with Read-Only Instances + Simple Message Queue (SMQ)
  • C Dedicated Host (DDH) + ApsaraDB for Redis + Resource Orchestration Service (ROS)
  • D Server Load Balancer (SLB) + Object Storage Service (OSS) + Cloud Enterprise Network (CEN)
Quiz Solution • Scenario 1

Scenario 1: Solution & Architectural Analysis

Correct Answer: B ECS with Auto Scaling + ApsaraDB RDS with Read-Only Instances + Simple Message Queue (SMQ).
Validated Architecture
✖ Option A is Incorrect
Wrong database model & queue scope. Tablestore is a NoSQL wide-column database rather than a relational database with read replicas, and Apache Kafka is designed for high-throughput stream ingestion rather than standard asynchronous job queue buffering.
✔ Option B is Correct
Validated multi-tier design. ECS with Auto Scaling dynamically scales compute instances based on CPU metrics, ApsaraDB RDS with Read-Only instances offloads read queries from the primary database, and SMQ provides point-to-point queue buffering to decouple downstream order fulfillment.
✖ Option C is Incorrect
Static capacity & wrong tools. Dedicated Hosts (DDH) do not dynamically auto-scale for spike traffic, Redis is an in-memory cache rather than a full relational database, and ROS is an IaC deployment automation tool rather than a message queue.
✖ Option D is Incorrect
Missing compute, database & queue tiers. SLB, OSS, and CEN provide traffic balancing, unstructured object storage, and enterprise transit networking, failing to address the auto-scaling compute, relational data, and asynchronous queue requirements.

Practice Scenario 2: Enterprise Hybrid & Multi-VPC Transit Networking

Question 2 A financial enterprise has deployed multiple production VPCs across Jakarta (ap-southeast-5) and Singapore (ap-southeast-1), alongside an on-premises enterprise data center connected via a physical Express Connect dedicated line. The enterprise network team requires a unified private transit architecture that guarantees: (1) secure, any-to-any private interconnectivity between all cloud VPCs and on-premises subnets, (2) enterprise-grade network quality with ultra-low jitter and packet loss rate below 0.2%, and (3) automated dynamic route propagation without maintaining dozens of static routing tables. Which solution should the architect implement?
  • A Assign public Elastic IP (EIP) addresses to all compute instances and configure software SSL-VPN tunnels over the public Internet.
  • B Deploy a NAT Gateway with SNAT and DNAT entries in each VPC and route private traffic across the public Internet.
  • C Deploy Cloud Enterprise Network (CEN) with Transit Routers (TR) attaching all regional VPCs and the on-premises Express Connect virtual border router.
  • D Configure point-to-point VPC Peering connections between every pair of VPCs and write manual static route entries for all CIDRs.
Quiz Solution • Scenario 2

Scenario 2: Solution & Architectural Analysis

Correct Answer: C Cloud Enterprise Network (CEN) with Transit Routers (TR).
Validated Architecture
✖ Option A is Incorrect
High latency & public exposure. Routing sensitive enterprise traffic over public EIPs and Internet SSL-VPN introduces unpredictable latency, high jitter, and violates requirements for dedicated private backbone transit.
✖ Option B is Incorrect
Public gateway misapplication. NAT Gateway provides outbound Internet access (SNAT) and port mapping (DNAT) for public communication; it is not designed to serve as an enterprise private transit backbone.
✔ Option C is Correct
Enterprise transit hub. Cloud Enterprise Network (CEN) with Transit Routers (TR) interconnects multi-region VPCs and Express Connect border routers over Alibaba Cloud's private global fiber network, delivering automated route propagation, <0.2% packet loss, and ≥99.95% availability.
✖ Option D is Incorrect
Complex mesh & non-transitive routing. Point-to-point VPC Peering does not support transitive routing through Express Connect into on-premises data centers and creates an unmanageable N*(N-1)/2 manual static route mesh.
Interactive Quiz • Scenario 3

Practice Scenario 3: Secure Least-Privilege Application Access

Question 3 A software development team is deploying a containerized microservice on private ECS instances in a VPC. The application must read configuration assets and upload transaction archives to an Object Storage Service (OSS) bucket. Corporate cybersecurity compliance strictly mandates: (1) permanent AccessKey pairs (AccessKey ID and AccessKey Secret) must NEVER be hardcoded into application source files or stored on virtual machine disks, and (2) all permissions must adhere to least-privilege access principles. How should the architect design this access architecture?
  • A Configure the Alibaba Cloud root account AccessKey in the instance operating system environment variables.
  • B Configure the OSS bucket Access Control List (ACL) to public-read and public-write so instances can access files without authentication.
  • C Create a dedicated RAM User with an OSS policy, generate a permanent AccessKey, and save the credentials into a local configuration file on each ECS disk.
  • D Create a RAM Role with a scoped OSS policy, attach the role to the ECS instance, and let the application retrieve temporary STS credentials via the Instance Metadata Service (IMDS).
Quiz Solution • Scenario 3

Scenario 3: Solution & Architectural Analysis

Correct Answer: D Attach an instance RAM Role and retrieve short-lived STS tokens via Instance Metadata Service (IMDS).
Validated Architecture
✖ Option A is Incorrect
Catastrophic credential exposure. Using root account credentials grants unrestricted administrative control over the entire cloud account and storing them in environment variables violates basic security compliance.
✖ Option B is Incorrect
Severe data exposure risk. Setting an OSS bucket to public-read and public-write allows anyone on the Internet to view, modify, or delete proprietary corporate data without authentication.
✖ Option C is Incorrect
Compliance violation. Storing long-lived permanent AccessKey credentials in local configuration files directly violates the enterprise mandate forbidding persistent credentials on disk drives.
✔ Option D is Correct
Cloud-native credential federation. Attaching an instance RAM Role enables applications to obtain temporary, auto-rotating Security Token Service (STS) credentials via Instance Metadata Service (IMDSv2), eliminating static stored keys and enforcing least privilege.
